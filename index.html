modapp

A lightweight Electron desktop app whose engine is genuinely bare: a top bar and an empty page. Everything you see, from the Home tab to the browser and the terminal, is a mod.

modapp, loaded from local files (no web server)
Enginebootstrap.js loads enabled mods and exposes ModAPI
Shellsite.js draws the top bar and an empty content area
Modsregister tabs and widgets, call native APIs through permissions

Since v2.0.0 modapp runs on a castLabs build of Electron (44.5.1+wvcus) so DRM sites such as Spotify can play inside the app. Windows and Linux packages are published; macOS is configured but not part of releases.

Run and build

npm install
npm start                 # launch in development
npm test                  # node --test electron/*.test.js
npm run build:windows     # NSIS installer
npm run build:linux       # AppImage, deb, rpm

Bundled mods are copied into a writable userData/mods folder on every launch, so edits to a bundled mod are reset on the next start. Mods you add yourself in that folder are left alone.

Writing a mod

Create mods/<your-mod-id>/ with a mod.json. The id is the folder name: letters, digits, _ and -, up to 64 characters.

{
  "name": "My Mod",
  "version": "1.0.0",
  "author": "you",
  "description": "What it does",
  "enabledByDefault": true,
  "apis": ["api.js"],
  "styles": ["style.css"],
  "scripts": ["script.js"],
  "permissions": ["fs.read", "fs.write"]
}
FieldMeaning
apisScripts loaded first, for every enabled mod, so other mods can use what they define.
stylesStylesheets, added after all apis have loaded.
scriptsLoaded one after another, core first, so a mod can rely on earlier mods having run.
permissionsNative capabilities the mod may use (see below). Without a permission the call is refused.

Asset paths must stay inside the mod's own folder: no absolute paths, no schemes or drive letters, and no .. segments.

Scope: mod scripts are plain script tags that share one global scope. A top-level const or let with the same name in two mods (for example MOD_ID) is a SyntaxError that stops the second script entirely. Wrap each script in an (function () { ... })(); block.

ModAPI

Every mod script runs with a global ModAPI.

ModAPI.registerTab({
  id: 'my-tab', label: 'My Tab', icon: 'star',   // Material Symbols Outlined name
  fullBleed: true,                                // no padding or max-width, fills the height
  render(container) { container.textContent = 'Hello'; },
});

ModAPI.registerWidget({
  id: 'my-widget', label: 'My Widget', icon: 'bolt',
  center: false, draggable: true, overlay: false,
  width: '420px', height: null, noChrome: false,
  mount(container, close) { container.textContent = 'In a panel'; },
});

ModAPI.overrideTab('my-tab', (container) => { /* replace how a tab renders */ });
ModAPI.onTabActivate('my-tab', (container) => { /* layer something on top */ });
ModAPI.setIdentity({ title: 'My App', icon: '★' });
ModAPI.registerSettingsSection({ id: 'mine', label: 'Mine', icon: 'tune', render(container) {} });
ModAPI.setMarkdown(element, markdownText);   // safe markdown into an element
  • render runs once, the first time a tab opens. After that the view is shown and hidden.
  • overlay: true dims the page and closes on click-outside or Esc. center plus overlay gives a settings-dialog look.
  • The last mod to call setIdentity wins. icon may be text, an http or file URL, or a data image URL.
  • ModAPI.renderMarkdown(text) returns escaped HTML. Links are limited to http, https and mailto and open in the system browser.
  • window.Icon(name, { size, color, title }) builds a Material Symbols icon element.

Native APIs and permissions

Desktop mods reach the operating system through ModAPI.native. Each call runs as the mod that made it, and the main process checks that mod's manifest before doing anything.

APIPermissionNotes
fs: ensureDir, readFile, readBytes, writeFile, writeBytes, readDir, exists, resolvePath, toFileUrl, removeFile, removeDir, movefs.ensure_dir, fs.read, fs.write, fs.read_dir, fs.remove, fs.moveRelative paths inside the mod's own data folder only. Absolute paths and .. are rejected, symlinks are resolved, 4 GiB quota per mod, reads capped at 256 MiB.
shell.run(command, cwd)shell.runRuns through the system shell. 30 second timeout, 1 MiB of output.
net.fetch(url)net.fetchFetches from the main process. Used by the Calendar for ICS feeds.
notifications.send(title, body)notifications.sendNative desktop notification.
dialog: pickFolder, pickFiles, pickSaveFiledialog.pickCancelling resolves to null or an empty list.
pty: shells, open, write, resizepty.accessReal pseudo-terminals through node-pty. open returns { session, label, close }.
webviewwebview.accessEmbedded pages, http and https only. Each mod gets its own cookie partition.
settings: read, writesettings.read, settings.writeApp settings, used by Core.
mods: list, togglemods.toggle to toggleEnable or disable a mod.
const fs = ModAPI.native.fs;
await fs.writeFile('notes/today.txt', 'hello');
const text = await fs.readFile('notes/today.txt');

const term = await ModAPI.native.pty.open({ cols: 80, rows: 24,
  onData: (chunk) => console.log(chunk), onExit: (code) => console.log(code) });
await term.close();

The preload bridge also exposes electronAPI.openExternal(url) (http, https, mailto) and electronAPI.onUpdateProgress(callback), which returns an unsubscribe function.

Updates

modapp updates itself with electron-updater from published GitHub releases (drafts are never offered).

  • On startup, and from Settings, Updates, an in-app dialog shows the version change, date and the release notes rendered as markdown.
  • Install and restart downloads with a progress bar, then restarts. Later closes the dialog; View on GitHub opens the release page.
  • The startup pop-up can be switched off (Show update pop-up). A small notice then appears in the bottom-right corner.
  • Release notes come from the GitHub release body. If GitHub is unreachable, the updater's own text is used.

Releases and CI

  1. Set the same version in package.json and the tag. The workflow refuses a tag that does not match.
  2. Push a v* tag. GitHub Actions runs the tests, then builds Windows (NSIS) and Linux (AppImage, deb, rpm).
  3. Packages are attached to a draft release. Write the notes in markdown, then publish it. Users are offered the update only after that.

Windows builds are VMP-signed through castLabs EVS in the afterSign hook, which needs the EVS_ACCOUNT_NAME and EVS_PASSWD repository secrets. Builds are not Authenticode-signed yet, so Windows SmartScreen may warn on first run. On Linux, a newly installed Widevine component needs a restart, so the app restarts itself once after installing it.

Security and trust

Mods are fully trusted code. Permissions limit what an honest mod can reach and make mistakes visible. They are not a sandbox against a hostile mod, so install only mods you trust.

  • Mod ids and asset paths are validated, and each mod's files and data live in separate folders.
  • Webviews load only http and https pages, with separate storage per mod.
  • Rendered markdown escapes all text first, so release notes cannot run script.
  • Installing an update no longer needs a native confirmation, so any installed mod can start one.
